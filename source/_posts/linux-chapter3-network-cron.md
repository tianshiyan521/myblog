测试环境最常见的三类问题：**连不上、端口没起、任务没跑**。

这篇整理对应的命令：`ping` / `netstat` / `ss` / `crontab`。

<!-- more -->

## 一、ping：先确认"能不能通"

```bash
ping 192.168.1.100          # 持续发包，Ctrl+C 停
ping -c 4 baidu.com         # 只发 4 次
```

### 三个实用参数

| 参数 | 作用 | 场景 |
|------|------|------|
| `-c N` | 发 N 次就停 | 脚本里用，避免无限等 |
| `-i N` | 发包间隔 N 秒 | 慢速 ping，避免触发防火墙限速 |
| `-W N` | 等待超时 N 秒 | 快速检测，别卡住 |

```bash
# 部署前确认目标机器可达
ping -c 3 10.0.0.50

# 快速检测（1 秒超时）
ping -W 1 -c 3 192.168.10.20
```

### ⚠️ ping 通了不代表服务可用

**这是最容易误判的一点。**

```
ping 通  →  网络层通  →  但服务端口可能没开
```

`ping` 用的是 ICMP 协议，**和你的服务端口完全无关**。

**正确顺序**：

```bash
ping -c 3 10.0.0.50          # ① 网络层通不通
telnet 10.0.0.50 8080        # ② 端口开不开
curl http://10.0.0.50:8080/  # ③ 服务响应正不正常
```

> 我遇到过好几次"网络没问题但连不上"，最后都是**服务没启动**或**防火墙拦了端口**。
> **ping 只能排除网络，不能证明服务可用。**

## 二、netstat / ss：谁占了端口

`netstat` 是老牌命令，`ss` 是它的现代替代品（**更快，大连接数下优势明显**）。

### 最常用的三条

**① 查看所有监听端口**

```bash
ss -tlnp
```

参数含义：

| 参数 | 含义 |
|------|------|
| `-t` | TCP |
| `-l` | **listening（监听中）** |
| `-n` | 显示数字端口（不解析成服务名） |
| `-p` | **显示进程**（需要 root 权限） |

**② 检查某端口是否被占用**

```bash
ss -tlnp | grep :8080
```

**这条命令在测试环境用得最多** —— 服务起不来，第一个怀疑就是"端口被占了"或"端口没监听"。

**③ 查看谁占用了特定端口**

```bash
ss -tlnp 'sport = :3306'    # 查谁占着 MySQL 端口
```

### 连接状态速查

```bash
ss -tan
```

| 状态 | 含义 |
|------|------|
| `LISTEN` | 监听中，等待连接 |
| `ESTABLISHED` | 已建立连接，正常通信 |
| `TIME_WAIT` | **主动关闭后等待 2MSL**（大量出现说明短连接很多） |
| `CLOSE_WAIT` | **对端已关闭，本端还没关** |
| `SYN_SENT` | 已发连接请求，等待响应 |

### ★ 压测时最该关注的两个状态

**① 统计当前活跃连接数**

```bash
netstat -an | grep ESTABLISHED | wc -l
```

压测时观察这个数字，能验证**并发数是否真的打上去了**。如果压测设了 100 并发，但 ESTABLISHED 只有 10，说明请求根本没并发到服务端。

**② `CLOSE_WAIT` 大量堆积 → ⚠️ 代码有 bug**

`CLOSE_WAIT` 的含义是"**对端已经关闭连接，但本端还没关闭**"。

正常情况应该很快消失。**如果持续堆积，说明程序没有正确关闭连接**——这是典型的**连接泄漏**，最终会耗尽端口或句柄。

| 状态堆积 | 含义 | 责任 |
|---------|------|------|
| 大量 `TIME_WAIT` | 短连接多 | 通常正常，可通过连接池优化 |
| **大量 `CLOSE_WAIT`** | **本端未关闭连接** | **⚠️ 应用代码问题，要提单** |

> **这个判断很实用**：测试时如果发现服务在压测后逐渐不可用，用 `ss -tan | grep CLOSE_WAIT | wc -l` 看一下。
> 如果是 CLOSE_WAIT 堆积，**这不是"性能不够"，是代码缺陷**，提单时可以直接给开发指方向。

## 三、crontab：定时任务

```bash
crontab -l       # 查看当前用户的任务
crontab -e       # 编辑
crontab -r       # ⚠️ 删除所有任务（危险）
crontab -u gameadm -l   # 查看指定用户（需 root）
```

### 时间格式（5 个字段）

```
*    *    *    *    *    command
│    │    │    │    │
│    │    │    │    └── 星期 (0-7, 0和7都是周日)
│    │    │    └─────── 月 (1-12)
│    │    └──────────── 日 (1-31)
│    └───────────────── 小时 (0-23)
└────────────────────── 分钟 (0-59)
```

### 游戏服务器维护实例

```bash
# 每天凌晨 3 点清理日志
0 3 * * * /opt/game/scripts/clean_logs.sh

# 每周一凌晨 2 点做数据库备份
0 2 * * 1 /opt/game/scripts/db_backup.sh

# 每 5 分钟检查服务是否存活，挂了就重启
*/5 * * * * /opt/game/scripts/health_check.sh
```

| 写法 | 含义 |
|------|------|
| `*/5` | 每 5 个单位 |
| `1-5` | 1 到 5 |
| `1,3,5` | 1、3、5 |

### ⚠️ 三个必踩的坑

**① crontab 里的命令必须用绝对路径**

cron 执行时的 `PATH` 和你登录后不一样，`python xxx.py` 很可能报"命令找不到"。

```bash
# ❌ 可能失败
0 3 * * * python /opt/script/run.py

# ✅ 用绝对路径
0 3 * * * /usr/bin/python3 /opt/script/run.py
```

**② 不会有任何输出，除非你重定向**

cron 执行失败是**静默的**——你不知道它跑了没跑、有没有报错。

```bash
# 把输出和错误都记到日志
0 3 * * * /opt/game/scripts/clean_logs.sh >> /var/log/clean.log 2>&1
```

> **配置文件里的 `>> /var/log/xxx.log 2>&1` 不是可选的美化，是必需的。**
> 没有它，定时任务出问题时你连去哪儿查都不知道。

**③ 环境变量缺失**

cron 的环境比你登录时干净得多，脚本里依赖的环境变量（如 `JAVA_HOME`）可能不存在。

**解决**：在脚本开头显式设置，或者直接 `source` 环境文件。

## 四、排查套路总结

**"服务连不上"排查顺序：**

```bash
ping -c 3 <host>              # ① 网络层
telnet <host> <port>          # ② 端口层
ss -tlnp | grep :<port>       # ③ 本机是否在监听
curl http://<host>:<port>/    # ④ 服务是否响应
tail -f /var/log/xxx.log      # ⑤ 看日志找原因
```

**"定时任务没跑"排查顺序：**

```bash
crontab -l                    # ① 任务在不在
grep CRON /var/log/syslog     # ② cron 有没有执行
cat /var/log/xxx.log          # ③ 脚本有没有报错（前提是做了重定向）
which python3                 # ④ 命令路径对不对
```

## 五、小结

| 命令 | 用途 | 关键点 |
|------|------|--------|
| `ping -c N` | 网络连通性 | **通了不代表服务可用** |
| `ss -tlnp` | 监听端口 | 检查端口占用/未监听 |
| `ss -tan` | 连接状态 | **CLOSE_WAIT 堆积 = 代码 bug** |
| `crontab -e/-l` | 定时任务 | **绝对路径 + 日志重定向** |

**两个最容易误判的点：**

1. **ping 通 ≠ 服务可用** —— ICMP 和服务端口无关
2. **CLOSE_WAIT 堆积不是性能问题** —— 是应用没关连接的代码缺陷

> **本课要点**：ping 只排除网络｜CLOSE_WAIT 堆积是代码问题｜cron 必须绝对路径 + 日志重定向
