**管道是 Linux 最强大的设计，也是测试人员最该掌握的一项技能。**

因为它把"看日志"这件事，从"一屏一屏翻"变成了"一条命令给出答案"。

## 一、管道与重定向基础

```bash
命令1 | 命令2            # 管道：命令1的输出 → 命令2的输入
命令 > 文件              # 覆盖写入
命令 >> 文件             # 追加写入
命令 < 文件              # 从文件读取输入
命令 2> 文件             # 错误重定向
命令 &> 文件             # 标准输出 + 错误一起重定向
```

| 符号 | 说明 |
|------|------|
| `\|` | 管道符，前一个命令的输出传给下一个 |
| `>` | 覆盖写（原内容清空） |
| `>>` | 追加写 |
| `<` | 输入重定向 |
| `2>` | 只重定向错误输出 |
| `&>` | 标准输出 + 错误一起重定向 |

### ★ `2>&1` 是什么

```bash
python test_script.py > output.log 2>&1
```

拆开看：

- `> output.log` — 把**标准输出**（fd 1）写到文件
- `2>&1` — 把**标准错误**（fd 2）重定向到**标准输出指向的地方**（也就是同一个文件）

**为什么要这样写？**

因为程序有两种输出：

| 流 | 内容 |
|----|------|
| stdout | 正常结果 |
| stderr | 报错信息 |

只写 `> output.log` 的话，**报错信息会直接打在屏幕上，不进日志文件**。

**加上 `2>&1`，两个流都进文件**，日志才完整。

> ⚠️ **顺序不能反**：`2>&1 > file` 是错的。
> 它的含义是"把 stderr 指到当前 stdout（屏幕），然后把 stdout 改到文件"——**结果错误信息还是打在屏幕上。**
>
> **记住写法：`> file 2>&1`，先指文件，再合并错误。**

## 二、日志分析的经典管道组合

### 核心套路

```
grep（筛行） → awk（切列） → sort（排序） → uniq -c（计数） → sort -rn（按数量倒序） → head（取前 N）
```

**这一条链路能解决大部分日志统计需求。**

### 实战 1：统计出现最多的错误类型

```bash
grep "ERROR" app.log | awk '{print $5}' | sort | uniq -c | sort -rn | head -10
```

拆解：

| 步骤 | 做什么 |
|------|--------|
| `grep "ERROR"` | 只留含 ERROR 的行 |
| `awk '{print $5}'` | 取第 5 列（假设是错误码） |
| `sort` | 排序（**`uniq` 只能处理相邻重复，必须先 sort**） |
| `uniq -c` | 去重并计数 |
| `sort -rn` | 按数量倒序 |
| `head -10` | 取前 10 |

> ⚠️ **`sort` 不能省**。`uniq` 只对**相邻**的重复行生效。
> 跳过 sort 直接 uniq，同一个值可能被统计成好几行 —— 这是新手最常见的错误。

### 实战 2：统计访问量 Top 10 的 IP

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
```

**这条命令是运维和测试的必备技能** —— 压测时验证流量是否均匀、排查是否有异常来源，都靠它。

### 实战 3：查某个玩家/用户的所有操作

```bash
grep "player_id=12345" server.log | grep -v "heartbeat"
```

`grep -v` 是**反向筛选**，排除干扰项。

**为什么要排除心跳？** 因为心跳日志量大且无信息量，会淹没真正有价值的记录。

### 实战 4：按时间段筛日志

```bash
sed -n '/2026-09-29 14:00/,/2026-09-29 15:00/p' server.log
```

`sed -n` 配合 `/开始/,/结束/p` 是**按范围打印**的标准写法。

### 实战 5：只输出匹配行的前后文

```bash
grep -A 5 -B 5 "NullPointerException" server.log
```

| 参数 | 含义 |
|------|------|
| `-A N` | 显示匹配行**后** N 行 |
| `-B N` | 显示匹配行**前** N 行 |
| `-C N` | 前后各 N 行 |

> **报错日志的关键信息往往不在报错那一行，而在前后几行。**
> 只 grep 报错行，你只知道"这里错了"；带上前后文，往往能看到"是什么请求触发的"。

## 三、awk 与 sed 进阶

### awk：按列处理

```bash
awk '{print $1, $3}' access.log              # 打印第 1、3 列
awk -F',' '{print $2}' data.csv              # 指定逗号分隔
awk '$3 > 100 {sum += $3; count++} END {print "avg:", sum/count}' data.txt
```

**awk 的核心价值是"按列"** —— 日志每一列含义不同，awk 让你能只取出需要的那一列。

**条件过滤 + 计算**是 awk 的杀手锏：

```bash
# 统计响应时间 > 100ms 的请求的平均耗时
awk '$3 > 100 {sum += $3; count++} END {print "avg:", sum/count}' data.txt
```

> **这类需求以前要写 Python 脚本，用 awk 一行就完了。**

### sed：按行处理

```bash
sed 's/error/ERROR/g' app.log        # 只输出替换结果，不改原文件
sed -i 's/old/new/g' file.txt        # -i 直接改原文件
sed -i '/^$/d' config.txt            # 删除空行
sed -n '2,5p' file.txt               # 只打印第 2-5 行
sed -i 's/8080/9090/g' *.conf        # 批量改端口
```

| 选项 | 说明 |
|------|------|
| `-i` | ⚠️ **直接修改原文件** |
| `-n` | 只打印处理过的行（配合 `p`） |
| `s/旧/新/g` | 全局替换（`g` 不能忘） |

### ⚠️ `sed -i` 是危险操作

```bash
sed -i 's/8080/9090/g' *.conf
```

**这条命令会直接修改所有匹配的文件，且没有撤销机会。**

**安全习惯：**

```bash
# ① 先不写 -i，看输出结果对不对
sed 's/8080/9090/g' app.conf

# ② 确认没问题再加 -i
sed -i 's/8080/9090/g' app.conf

# ③ 或者先备份
cp app.conf app.conf.bak && sed -i 's/8080/9090/g' app.conf
```

> **和数据库的 `DELETE` 一样，`sed -i` 的破坏力被严重低估。**
> 一条命令改错，配置文件全废。

## 四、vim 速查（够用版）

```bash
vim app.log          # 打开
vim +500 app.log     # 打开并跳到第 500 行
vim +/ERROR app.log  # 打开并跳到第一个 ERROR 处
vim -R config.txt    # 只读模式（防误改）
```

**只需记住这几组：**

| 操作 | 命令 |
|------|------|
| 进入编辑 | `i` |
| 退出编辑 | `Esc` |
| 保存退出 | `:wq` |
| 不保存退出 | `:q!` |
| 搜索 | `/关键词`，`n` 下一个 |
| 跳行 | `:N` |
| 撤销 | `u` |

> **`vim +/ERROR app.log` 这招在排查日志时很好用** —— 直接跳到出错位置，不用手动翻。
>
> 顺序是：`vim +/关键词 文件`，先定位再查看。

## 五、一份实用的日志分析速查表

| 需求 | 命令 |
|------|------|
| 实时看日志 | `tail -f app.log` |
| 实时看含 ERROR 的行 | `tail -f app.log \| grep --line-buffered ERROR` |
| 看最后 100 行 | `tail -100 app.log` |
| 统计错误总数 | `grep -c ERROR app.log` |
| 统计错误类型分布 | `grep ERROR app.log \| awk '{print $5}' \| sort \| uniq -c \| sort -rn` |
| 查某用户操作（排除噪音） | `grep "uid=123" app.log \| grep -v heartbeat` |
| 查时间段 | `sed -n '/14:00/,/15:00/p' app.log` |
| 带上下文看报错 | `grep -A 5 -B 5 ERROR app.log` |
| 统计 IP Top 10 | `awk '{print $1}' access.log \| sort \| uniq -c \| sort -rn \| head -10` |
| 结果存文件（含错误） | `cmd > out.log 2>&1` |

## 六、小结

| 要点 | 内容 |
|------|------|
| **管道范式** | grep → awk → sort → uniq -c → sort -rn → head |
| **`2>&1`** | 先指文件再合并错误；写反了错误信息不进文件 |
| **`sort` 不能省** | `uniq` 只处理相邻重复行 |
| **awk 强在按列** | 条件过滤 + 计算，一行搞定 |
| **sed -i 危险** | 先不加 `-i` 看结果，或先备份 |
| **grep -A/-B** | 报错的关键信息常在上下文里 |

> **本课要点**：管道是日志分析的核心｜uniq 前必须 sort｜2>&1 顺序不能反｜sed -i 会直接改文件
