MySQL 是测试工程师进阶的**分水岭技能**。会不会写 SQL，直接决定了你在排查问题时是"等开发查日志"还是"自己上手定位"。

本专栏按 30 天计划整理，从零语法到实战应用。

## 为什么测试要学 MySQL

三个最实在的理由：

**① 验证数据真的落库了**

接口返回 `code=0` 之后呢？金币真的加了吗？订单真的写进去了吗？只信接口响应是自欺欺人——**要去数据库里确认。**

**② 自己造测试数据**

要测 100 级的角色、要测背包满的场景、要测 30 天没登录的账号——找开发帮你改数据，不如自己一条 SQL 改完。

**③ 排查问题定位更快**

线上反馈"道具没到账"，你能直接查：

```sql
SELECT * FROM user_item 
WHERE user_id = 12345 AND item_id = 8888 
ORDER BY create_time DESC LIMIT 10;
```

**没有记录 → 是没发下来**；**有记录但状态异常 → 是发放逻辑问题**。这一条查询就能把问题甩给正确的方向。

## 给测试的两个提醒

### 提醒一：只学 SELECT 是远远不够的

测试场景里经常需要 **UPDATE 和 DELETE**：

```sql
-- 重置某个玩家的每日任务进度，方便重复测试
UPDATE user_daily_task 
SET progress = 0, status = 0 
WHERE user_id = 12345 AND task_date = CURDATE();
```

不会写 UPDATE，你测个每日重置功能就得等第二天。

### 提醒二：线上环境慎用 DML

```sql
-- ⚠️ 这条 SQL 上线前请把 WHERE 条件读三遍
DELETE FROM user_item WHERE user_id = 12345;
```

**安全习惯**：

1. 动手前先 `SELECT` 一遍，确认影响范围
2. 加 `LIMIT` 限制影响行数
3. 生产库操作前**先备份**，或者至少先 `SELECT ... FOR UPDATE` 试一下
4. 能用测试环境就别碰生产
